# v0.0.7 — Backup cifrati

- **Data**: 2026-10-17
- **Contiene**: la cifratura delle istantanee (Anello di Gige) con passphrase e codice di recupero, i comandi `zbone backup setup`, `passphrase`, `recover` e `list --details`.
- **Criteri di accettazione**
  - [x] `backup setup` chiede la passphrase due volte (almeno 10 caratteri), mostra il codice di recupero una volta sola e chiede di scriverne l'ultimo gruppo; se non corrisponde non salva nulla.
  - [x] Dopo il setup le istantanee esistenti sono cifrate al loro posto, solo dopo aver controllato che la copia cifrata si apre ed è identica.
  - [x] Le istantanee nuove, anche automatiche, sono cifrate senza chiedere nulla.
  - [x] Ripristino e verifica di un'istantanea cifrata chiedono la passphrase; una passphrase sbagliata dà un messaggio breve e non cambia nulla.
  - [x] `backup passphrase` e `backup recover` cambiano la passphrase; il codice di recupero resta lo stesso.
  - [x] Una sola istantanea copiata su un altro dispositivo si apre con il codice di recupero.
  - [x] `keys.json` non contiene mai la passphrase né la chiave privata in chiaro.
  - [x] `pytest` passa (147 test).
- **Scelte**
  - La passphrase protegge una chiave di lungo periodo invece di cifrare ogni file: i backup automatici restano silenziosi e cambiare passphrase è istantaneo.
  - scrypt invece di Argon2id: è già in `cryptography`, senza dipendenze in più.
  - Il database sul dispositivo resta in chiaro (è protetto dall'account del sistema operativo); cifrarlo è una richiesta della fase 0.2 (dati sensibili).
- **Come provarla**: `zbone backup setup`, poi `zbone backup list` (le istantanee risultano "cifrata") e `zbone backup verify`. Dettagli in [cifratura](../tecnica/backup.md#cifratura--anello-di-gige-dalla-007).
