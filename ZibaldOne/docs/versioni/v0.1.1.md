# v0.1.1 — Prima versione per i tester

- **Data**: 2026-10-17
- **Contiene**: l'APK Android costruito da GitHub Actions e allegato alle release, il controllo degli aggiornamenti nell'app e nella CLI, la guida per i tester ([distribuzione](../tecnica/distribuzione.md), [rilascio Android](../sviluppo/rilascio-android.md)).
- **Criteri di accettazione**
  - [x] Un tag `zibaldone-vX.Y.Z` fa partire la build: test, APK `ZibaldOne-X.Y.Z.apk` firmato, release *pre-release* con la nota della versione.
  - [x] Il workflow si ferma se il tag non corrisponde alla versione nel codice; si può rilanciare a mano con un tag.
  - [x] Il numero di build Android cresce sempre con la versione (0.1.1 → 1001).
  - [x] L'app controlla al massimo una volta al giorno, solo dopo l'avviso privacy; senza rete non dà errori e ricorda l'ultima risposta.
  - [x] Il controllo si spegne dall'app e da `zbone update --no-auto`; l'avviso privacy (versione 5) lo spiega.
  - [x] `pytest` passa senza rete: il client HTTP vero è bloccato nei test.
- **Scelte**
  - Le release dell'APK sono *pre-release*: l'app le conta lo stesso, ma su GitHub è chiaro che sono versioni di prova.
  - Il client OAuth e la chiave di firma stanno nei segreti di GitHub, mai nella repo.
  - Il controllo usa l'API pubblica di GitHub senza account: niente server nostri, niente dati dell'utente.
- **Non ancora verificato**: la build vera su GitHub Actions (servono i segreti e la repo pubblica), l'installazione su un telefono, l'accesso Google su Android.
- **Limiti noti**: GitHub non fa partire la build se si mandano più di tre tag insieme: la prima volta va lanciata a mano ([rilascio Android](../sviluppo/rilascio-android.md)). Su Android l'aggiornamento si installa a mano, scaricando l'APK.
- **Come provarla**: `zbone update`; per l'APK, i passi in [rilascio Android](../sviluppo/rilascio-android.md).
