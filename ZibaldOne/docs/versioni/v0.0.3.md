# v0.0.3 — Modelli e voci

- **Data**: 2026-10-17
- **Contiene**: i 12 tipi di blocco, i modelli fatti di blocchi, le voci, il database SQLite con migrazioni, i comandi `zbone template …` e `zbone entry …`, lo script di rilascio.
- **Criteri di accettazione**
  - [x] Si crea un modello con le domande, in una riga (`--block chiave:tipo:Etichetta!`, `--option blocco.opzione=valore`) o da un file JSON.
  - [x] Un modello con un blocco sconosciuto, un'opzione sconosciuta o due blocchi con la stessa chiave non viene salvato, e il messaggio dice perché.
  - [x] Si aggiunge una voce con le domande o con `--set`; un blocco obbligatorio vuoto blocca il salvataggio.
  - [x] `entry list` filtra per modello e per giorno; `entry show`, `edit` e `delete` accettano le prime 4 lettere dell'id.
  - [x] `entry edit --set blocco=` svuota un blocco; `--day` sposta la voce.
  - [x] Un modello con voci non si può eliminare.
  - [x] Modelli e voci passano da JSON e ritorno identici.
  - [x] Un database creato da una versione più nuova viene rifiutato senza toccarlo.
  - [x] `pytest` passa (56 test).
- **Scelte**
  - I blocchi pensati per la v0.0.4 (`longtext`, `date`, `checklist`, `scale`, `choice`, `progress`, `bookmark`, `link`) sono entrati già qui, perché i modelli pronti della v0.0.4 ne hanno bisogno e testarli insieme costava meno. La v0.0.4 resta quella dei modelli pronti.
  - I valori sono salvati in JSON dentro SQLite: ogni modello ha blocchi diversi e non serve cambiare tabelle quando ne inventi uno.
  - La versione vive solo in `src/zibaldone/__init__.py`, così non può essere diversa tra pacchetto e app.
- **Come provarla**: vedi la [guida rapida](../utente/guida-rapida.md), per esempio `zbone template create Libro --block "titolo:text:Titolo!" --block voto:rating`, poi `zbone entry add libro`.
